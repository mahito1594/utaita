# ユーザーストーリー (正本)

> この日本語版が正本。フェーズの区切りで英語版 [stories.md](./stories.md) に同期する。

形式: 1 ストーリー 1 行。自明でない場合のみ受け入れ条件を添える。フェーズごとにグループ化し、未割り当てのアイデアは Icebox へ。

> 状態: Phase 1 は 2026-07-07 のキックオフで精査済み。Phase 2 以降はロードマップから起こした初期ドラフトのままなので、pleroma-fe への実際の不満を観察して書き直していくこと。

## Phase 0 — 基盤

ユーザーストーリーの代わりに、一本の縦串を Done 条件とする:

- [x] dev proxy + 型生成済みクライアント経由でリファレンスインスタンスのタイムラインを取得し、アプリシェル (ラフ) 内に Status カードのリストとして描画できる。dev トークンは env から注入し、未設定なら 401/403 (エンドポイントで異なる — PLAN の落とし穴参照) がハンドリングされて UI に現れる。(2026-07-06 確認: 200 経路はブラウザ実機、401/403 はページテスト + 実インスタンスへの素の fetch で確認)

## Phase 1 — 閲覧 MVP

**Done 条件**: 下記ストーリーがすべてチェックされ、スマホ実機と PC の両方で成立している (片手での操作範囲、横スクロールなし)。かつ、閲覧については pleroma-fe を開かずに 1 日過ごせる。

- [ ] インスタンスのアカウントでログインでき、ブラウザを再起動してもログイン状態が保持される。ログアウトすると確実に未認証状態に戻る (Akkoma は Bearer リクエストにセッション Cookie も返す — PLAN の落とし穴参照)。
  - 未ログインで開いた URL がログイン後も維持される (2026-08-09 実装完了。スレッドの permalink が共有可能な URL になり、「リンクを踏む → 未ログイン → サインイン → 投稿を見失う」が現実の痛みになったため、スレッド表示と同セッションで実装)。開始時のアプリ内パスを sessionStorage に保存し、復帰時に**パースしてから**使う — 同一オリジンの別コードが書ける保存領域なので、戻り先は信用できない入力として扱い、アプリ内パス以外は `/` に落とす。ブラウザでの往復は未検証 (未ログイン状態と authorize 同意が要るため)
- [ ] Home タイムラインを滑らかな無限スクロールで読める。CW を開いてもスクロール位置がずれない。
- [ ] 開きっぱなしのタイムラインで、ページを再読み込みせずに新着を読み込める。
  - 手動更新 (ボタンないしプルリフレッシュ)。前方取得 (`since_id`; 応答が満杯なら未取得の区間があるとみなしてセグメント境界の GapMarker から埋め直す) の合流処理は store / segment 層に持ち、UI からは切り離しておく — Phase 4 の Streaming / 自動更新トグルが同じ合流処理を再利用する
  - refresh ボタンで新着を読み込んだら最上端へスクロールする (2026-08-08 Icebox から昇格 — dogfooding で「トップに行かない」違和感が実際に出た。refresh は明示アクションなので新着を目の前に出す。読みかけ位置に戻りたいケースの設計 — 据え置きスクロールや gap row 動線の温存 — は実装時に判断)。2026-08-11 の dogfooding 初日にも再指摘 (2 回目) — 優先度上げの根拠
- [ ] home / local / bubble / federated を切り替えて読める。(2026-08-08 実装完了: パスベース 4 ルート + バー内タブ、切替時は再フェッチ (読み位置保持は Icebox 済み項目)。エンドポイント/クエリの対応はページテストで確認。PC ブラウザ実機で確認 (2026-08-08): 4 タブ切替と aria-current、`local=true` の実効 (ローカル投稿のみ)、bubble の中身、federated のリモート混在、無限スクロール + 手動更新、375px でタブ + refresh ボタンが本文横スクロールなしで収まる。スマホ実機確認待ち)
- [ ] Status カードで投稿の中身が一通り読める: 本文 (HTML)、添付メディア、CW/sensitive、カスタム絵文字、ブースト元、絵文字リアクション、投票、リンクプレビュー。(2026-07-13 実装完了。PC ブラウザ実機で確認: 引用ミニカード、リンクプレビュー、リモート絵文字リアクション、終了済み投票、sensitive + blurhash 欠落フォールバック、CW 開閉のスクロール非ずれ、375px 横スクロールなし。スマホ実機確認待ち。進行中投票はページテストのみ、video 添付は実データ未遭遇のため未検証)
  - 本文はサニタイズ済み HTML として描画。`<small>` など pleroma-fe が取りこぼす基本タグも正しく表示する。MFM 専用描画には対応しない (`content` の HTML をそのまま描画)
  - メディアは 2 列グリッドで全枚数表示 (1 枚なら全幅)、タップで簡易オーバーレイ原寸。動画/音声はネイティブ `<video>`/`<audio>`。スワイプ送り付きライトボックスは Icebox。リモート添付の `blurhash`/`meta` 欠落で落ちない。sensitive メディアはデフォルトで隠れる
  - 投票は閲覧のみ (選択肢・票数・締切/終了状態)。リンクプレビューはタイトル+サムネイルの軽量版
  - 本文中のメンションはアプリ内のプロフィールへ。外部リンクは新しいタブで開く (ADR-0011)
  - 引用は深さ 1 のミニカードとして本文下に描画 (2026-07-13 決定 — ADR-0007)。描画時は本文の `span.quote-inline` (サーバ付加の RE: リンク) を除去。`quote` が null (未取得リモート等) やミニカード内のさらなる引用は RE: リンクのまま残す
  - 絵文字リアクション・ブースト・ファボの「誰が」一覧はカードには置かず、投稿詳細 (スレッド) ビューの持ち物 (会話ツリーのストーリーで実装)
- [ ] 投稿を開いて会話ツリー全体を読める。どの投稿から来たのか見失わない。(2026-08-09 実装完了 — ADR-0014。カード全体タップで `/statuses/:id` へ、枝優先・インデント 0・折りたたみなし、`/context` の ancestors/descendants は信用せず `in_reply_to_id` からツリーを再構築。ブラウザ実機で確認: 起点への着地、スレッドからスレッドへ潜っての再着地と戻ったときの復元、メンション/外部リンク/メディア/テキスト選択がカードのタップに吸われないこと、375px 横スクロールなし。引用ミニカードと `<video>`/`<audio>` は実データ未遭遇のためページテストのみ。スマホ実機確認待ち)
  - 親がインスタンス未取得 (`in_reply_to_id: "_"` — PLAN の落とし穴参照) の場合、**未取得の時点でプレースホルダーを出し、そこに明示的な取り込み操作を置く**。自動 resolve はしない — 1 回 2.6 秒かかるうえインスタンス DB への書き込みとリモートへのリクエストであり、さらに `/api/v2/search` は解決できないと AP ID の全文検索にフォールバックするので黙って別の投稿を親として表示しうる (ADR-0011 amendment)。元インスタンスへのリンクは外部と明示した副次的な導線としてボタンの隣に添える
  - **リモート投稿を明示的に取り込めること自体が差別化点** — akkoma-fe にこの機能は無く、`"_"` が truthy なので死んだリンクを出す (2026-08-09 にコード追跡で確認)
  - スレッドを開いて戻ったときにタイムラインの読み位置と蓄積したページを失わない (2026-08-09 実装完了、スレッド本体より先行。ブラウザ実機で確認: 185 件蓄積して離脱・復帰で全件と `scrollY` が復元され再取得なし、タブ切替は従来どおり再取得。ADR-0004 amendment)。**戻る導線は history back でなければならない** — スクロール復元は pop でのみ効く
- [ ] 絵文字リアクション・ブースト・ファボの「誰が」一覧をスレッド (投稿詳細) から開ける (`/api/v1/pleroma/statuses/:id/reactions`、`/reblogged_by`、`/favourited_by` — 形は実装セッション冒頭に実測)。2026-08-09 に会話ツリーのストーリーから分離: 一覧の設計 (どこに出すか、誰の一覧を優先するか) は会話ツリーとは独立した判断で、まとめると片方の未確定がもう片方を止める
- [ ] プロフィールを投稿 / 返信 / メディアのタブ付きで閲覧できる。フォロー関係 (フォロー中 / されている) が見える。
- [ ] 通知を読める。メンション・ブースト・フォロー・絵文字リアクションが一目で区別でき、`pleroma:emoji_reaction` や `move` など未知の type で落ちない。
- [x] タイムラインとスレッドの status 表示を full-bleed + 罫線に改める (2026-08-11 dogfooding 指摘 4・5・7 の統合。per-status のカード枠・角丸・gap が縦密度と本文幅を削るため廃止し、行 (左右 inset 12px + border-bottom 1px) にする。デスクトップはカラム単位で panel を着せ、QuoteCard は引用の異質さを示す信号としてカードのまま。スレッドは背骨ルールを画面端に置き本文 inset を左右対称にする — subject の 2 チャンネルマークは維持。判断理由と棄却案は [docs/design/timeline-density.md](./design/timeline-density.md))
- [ ] スレッド画面の小修正まとめ (2026-08-11 dogfooding 指摘 3・8・9・11・14。密度改修の後に着手 — 見た目の土台が先): Back ボタンのアイコン化と "Conversation" 見出しの整理 (canGoBack の出し分けは維持、SR 向け見出しの残し方は実装時判断) / スレッド内の投稿時刻を時刻精度で表示 (タイムラインカードは日付のまま。time.ts のロケール "en" には触れない — Phase 4) / UnfetchedParent をプレースホルダーカード化 (取得成功時のフォーカス移動先の設計と同時に — 起票済みチップ参照) / カスタム絵文字の拡大 (本文 1.25em ≈ 20px は akkoma-fe 実測 38px の約半分。新密度の画面で視覚調整) / "Not connected to this post" セクションの見出し + 説明文を面の先頭のヘッダー帯に収める (2026-08-11 指摘 14 追加 — 密度改修で前後が面になり、canvas 上の裸のテキストの浮きが目立つようになった) / 絵文字リアクションのチップも本文と同寸に拡大 (2026-08-15 指摘 15 追加 — 本文を 2em にしたことでチップの実寸 15px が相対的に目立つようになった。akkoma-fe も本文とリアクションを同寸で描く。件数の数字はメタ情報として xs 据え置き)

## Icebox

- 見逃した投稿のキャッチアップダイジェスト (Phanpy 風)
- タブを閉じても消えない下書き
- Streaming によるタイムラインのリアルタイム更新 — 自動更新 / 手動更新をトグルで切り替えられる形で (昔の Twitter クライアント風)
- 複数アカウント
- タイムラインごとのスクロール位置保持 (Phase 1 キックオフで削除 — home 常駐の利用実態では益が薄い。dogfooding で必要になったら)。2026-08-09 に**一部だけ昇格**: 「直前に見ていた 1 本を、詳細ルート (スレッド / プロフィール) へ出て戻る間だけ保持する」は実装済み (ADR-0004 amendment)。スレッド表示が入ると「返信を開いて戻る」が最頻の操作になり、そのたびに先頭から再取得するのは Done 条件に届かないため。**タイムライン間の切替での保持はここに残す** — 切替は push でスクロール復元が効かず、保持すると「古い内容・先頭・フェッチなし」という再取得より悪い状態になる
- スワイプ送り・ピンチズーム付きのメディアライトボックス
- ハッシュタグタイムライン (`/api/v1/timelines/tag/{tag}`)
- リストタイムライン (`/api/v1/timelines/list/{list_id}`)
- DM の閲覧 (spec のタイムライン一覧に direct が無い — Akkoma の chats 機構の調査から)
- リモートにしか存在しない返信の補完 (発言元インスタンスの公開 API をマージする差別化機能。同一オリジン前提と衝突するため要設計)
- カード時刻表示の再設計: 相対時刻 ("5m") が良いデザインかは要議論 — dogfooding で不満が出るか観察し、材料が揃い次第議論。2026-08-11 dogfooding: タイムラインカード側には不満なし。スレッド画面の時刻表示だけを Phase 1 の小修正として分離・先行し、全体再設計 (精度・TZ 設定) はここで観察継続。現状の絶対時刻はカレンダー表示 ("Jul 5") がブラウザのローカル TZ (Intl デフォルト)、ツールチップ (`title`) は API の生 ISO 文字列。理想は利用者が設定でタイムゾーンを選べること。実装スロットは Phase 4 の i18n と同時 (time.ts はロケールも "en" ハードコードで、同じ箇所を触るため — PLAN 参照)
- About 画面 + `/THIRD_PARTY_LICENSES.md` へのリンク(Vite の `build.license` で自動生成)。同時にバグ報告リンク等を `package.json` の `bugs.url` から import する形にする。attribution ファイルの補完性(現状 blurhash のように upstream で LICENSE 欠落の依存が空 body で並ぶ)は実装時に判断し、必要なら `rollup-plugin-license` で SPDX テキストを合成する fallback を検討。実装スロットは i18n / 設定画面ができるタイミング — Phase 4 想定
- closed な poll の最終結果を re-fetch する (2026-08-11 dogfooding 指摘。リモート発の poll は連合で届いた時点の票数しか無い。Akkoma ソース実査済み: `GET /api/v1/polls/:id` が唯一の refetch 誘発 API — リモートオブジェクトかつ前回更新から 60 秒超なら発言元へ HTTP GET して票数・closed を取り込む。openapi.json に定義あり。実装案: スレッド表示時に polls/:id を 1 発叩いて store の poll を差し替える。表示ごとの追加リクエスト 1 本の価値と、リモート先が落ちている場合の遅延・失敗の扱いが論点)
- 翻訳ボタン (2026-08-11 dogfooding 指摘。akkoma-fe 同等機能。API は openapi.json に一式: Akkoma 式 `GET /statuses/{id}/translations/{language}` と Mastodon 式 `POST /statuses/{id}/translate`、対応言語一覧 `/api/v1/instance/translation_languages`。エンドポイント選択と UI は実装時設計。前提: インスタンス側に翻訳バックエンド設定 — ringed.space は DeepL 設定済みで検証可能。派生タスク: README 拡充 — インスタンス設定に依存する機能とその前提を運用者向けに英語で明記し、未設定インスタンスでの UI の振る舞いも決めて揃える)
- 長文投稿の「もっと見る」折りたたみ (2026-08-11 dogfooding 指摘。akkoma-fe は max-height 超過で "Show more"。CW の開閉機構に「高さ超過による折りたたみ」を乗せられるかは実装時検討。CW で実績のある「開閉してもスクロール位置がずれない」を折りたたみ解除でも守ること)
- タイムラインの older 取得を per-anchor に並列化 — 現在は複数 GapMarker/Sentinel の要求を単一キューで直列消化しており、他アンカーの完了を待つ体感がある。並列化すると `appendOlder` の merge 経路 (先行応答で anchor 対象セグメントが吸収される可能性) と `exhausted` の帰属条件を再設計する必要があるため、dogfooding で「他 gap の待ちが実害になる頻度」を観察してから判断。
