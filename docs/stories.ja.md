# ユーザーストーリー (正本)

> この日本語版が正本。フェーズの区切りで英語版 [stories.md](./stories.md) に同期する。

形式: 1 ストーリー 1 行。自明でない場合のみ受け入れ条件を添える。フェーズごとにグループ化し、未割り当てのアイデアは Icebox へ。バグと story を伴わない負債 (リファクタ、ガードの欠落) は GitHub issue に置く — コードの実装・確認状況と同期する必要が無いため。

> 状態: Phase 1 は完了 (Done 条件は Phase 1 冒頭)。Phase 2 以降はロードマップから起こした初期ドラフトのままなので、kickoff で pleroma-fe への実際の不満に照らして書き直すこと。

## Phase 0 — 基盤

ユーザーストーリーの代わりに、一本の縦串を Done 条件とする:

- [x] dev proxy + 型生成済みクライアント経由でリファレンスインスタンスのタイムラインを取得し、アプリシェル (ラフ) 内に Status カードのリストとして描画できる。dev トークンは env から注入し、未設定なら 401/403 (エンドポイントで異なる — PLAN の落とし穴参照) がハンドリングされて UI に現れる。

## Phase 1 — 閲覧 MVP

**Done 条件**: 下記ストーリーがすべてチェックされ、スマホ実機と PC の両方で成立している (片手での操作範囲、横スクロールなし)。かつ、閲覧については pleroma-fe を開かずに 1 日過ごせる。例外は通知: 通知は既読管理と組でなければ dogfooding にならず、既読を付ける API が全部 write scope なので Phase 2 の持ち物。通知を見るために pleroma-fe を開くのは Done の判定に数えない。

- [x] インスタンスのアカウントでログインでき、ブラウザを再起動してもログイン状態が保持される。ログアウトすると確実に未認証状態に戻る (Akkoma は Bearer リクエストにセッション Cookie も返す — PLAN の落とし穴参照)。
  - 未ログインで開いた URL がログイン後も維持される。スレッドの permalink は共有可能な URL なので、「リンクを踏む → 未ログイン → サインイン → 投稿を見失う」を防ぐ。戻り先は同一オリジンの別コードが書ける保存領域から読むため、信用できない入力として扱い、アプリ内パス以外は `/` に落とす
- [x] 公開投稿の共有リンク (スレッド、その下の一覧、プロフィール) をログインなしで読める。非公開の投稿やインスタンスの設定で見えないものは「サインインすると見えるかもしれない」と案内し、その場からサインインできる ([ADR-0015](./adr/0015-sign-in-gates-only-personal-surfaces.md))。門はタイムライン 4 ルートにだけ残し、可視性の判定はしない — サーバの 401 / 403 / 404 に従う (Akkoma の匿名応答は PLAN の落とし穴参照)。local / federated の匿名閲覧は含めない — 共有リンクは投稿か人であってフィードではない。「ログイン後に元 URL へ戻る」導線は非公開投稿を開いた場合に引き続き必要
- [x] Home タイムラインを滑らかな無限スクロールで読める。CW を開いてもスクロール位置がずれない。
- [x] 開きっぱなしのタイムラインで、ページを再読み込みせずに新着を読み込める。
  - 手動更新 (ボタンないしプルリフレッシュ)。前方取得 (`since_id`; 応答が満杯なら未取得の区間があるとみなしてセグメント境界の GapMarker から埋め直す) の合流処理は store / segment 層に持ち、UI からは切り離しておく — Phase 4 の Streaming / 自動更新トグルが同じ合流処理を再利用する
  - refresh で新着を読み込んだら最上端へスクロールする。refresh は明示アクションなので新着を目の前に出し、成功時は新着 0 件でも常にトップへ (明示アクションへの応答を状況で変えない)、失敗時は読み位置を維持。「読みかけ位置に戻る」動線は持たない — 満杯応答時の GapMarker から辿れる動線で足りる。ページ破棄後に届いた refresh が次のルートの読み位置を奪わない。テストで押さえられない一点: 深くスクロールした状態でフルページを prepend したとき、ブラウザのスクロールアンカリングが `scrollTo(0, 0)` と競合しないかは happy-dom に layout がないため到達できない
- [x] home / local / bubble / federated を切り替えて読める。パスベース 4 ルート + バー内タブ、切替時は再フェッチ (切替での読み位置保持は Icebox)。
- [x] Status カードで投稿の中身が一通り読める: 本文 (HTML)、添付メディア、CW/sensitive、カスタム絵文字、ブースト元、絵文字リアクション、投票、リンクプレビュー。
  - 本文はサニタイズ済み HTML として描画 ([ADR-0013](./adr/0013-dompurify-html-pipeline.md))。`<small>` など pleroma-fe が取りこぼす基本タグも正しく表示する。MFM 専用描画には対応しない (`content` の HTML をそのまま描画)
  - メディアは 2 列グリッドで全枚数表示 (1 枚なら全幅)、タップで簡易オーバーレイ原寸。動画/音声はネイティブ `<video>`/`<audio>` (実データ未確認)。スワイプ送り付きライトボックスは Icebox。リモート添付の `blurhash`/`meta` 欠落で落ちない。sensitive メディアはデフォルトで隠れる
  - 投票は閲覧のみ (選択肢・票数・締切/終了状態。進行中の投票は実データ未確認)。リンクプレビューはタイトル+サムネイルの軽量版
  - 本文中のメンションはアプリ内のプロフィールへ。外部リンクは新しいタブで開く (ADR-0011)
  - 引用は深さ 1 のミニカードとして本文下に描画 (ADR-0007)。描画時は本文の `span.quote-inline` (サーバ付加の RE: リンク) を除去。`quote` が null (未取得リモート等) やミニカード内のさらなる引用は RE: リンクのまま残す
  - 絵文字リアクション・ブースト・ファボの「誰が」一覧はカードには置かず、投稿詳細 (スレッド) ビューの持ち物 (「誰が」一覧のストーリー)
  - カード全体タップが会話を開くカード (タイムライン・祖先・子孫・引用ミニカード) は `cursor: pointer`。開かないカード (スレッドの起点自身) は矢印のまま。片方だけ直すと「押せるカード / 押せないカード」の信号が嘘になるので、StatusCard と QuoteCard を揃える。引用ミニカードのタップは実データ未確認
- [x] 投稿を開いて会話ツリー全体を読める。どの投稿から来たのか見失わない ([ADR-0014](./adr/0014-thread-view.md))。カード全体タップで `/statuses/:id` へ、枝優先・インデント 0・折りたたみなし。`/context` の ancestors/descendants は信用せず `in_reply_to_id` からツリーを再構築する (PLAN の落とし穴参照)。メンション / 外部リンク / メディア / テキスト選択はカードのタップに吸われない
  - 親がインスタンス未取得 (`in_reply_to_id: "_"` — PLAN の落とし穴参照) の場合、**未取得の時点でプレースホルダーを出し、そこに明示的な取り込み操作を置く**。自動 resolve はしない — 1 回 2.6 秒かかるうえインスタンス DB への書き込みとリモートへのリクエストであり、さらに `/api/v2/search` は解決できないと AP ID の全文検索にフォールバックするので黙って別の投稿を親として表示しうる (ADR-0011 amendment)。元インスタンスへのリンクは外部と明示した副次的な導線としてボタンの隣に添える
  - **リモート投稿を明示的に取り込めること自体が差別化点** — akkoma-fe にこの機能は無く、`"_"` が truthy なので死んだリンクを出す
  - スレッドを開いて戻ったときにタイムラインの読み位置と蓄積したページを失わない (ADR-0004 amendment)。タブ切替は再取得。**戻る導線は history back でなければならない** — スクロール復元は pop でのみ効く
  - 引用関係で会話に繋がる detached の連なりは "Not connected to this post" に出さない。Akkoma が非返信の引用投稿に被引用投稿の context を継承させるため、引用の `/context` に被引用側のスレッドが混ざる (PLAN の落とし穴参照)。被引用投稿はミニカードで見えているので落としても失うものは無い。detached の機構自体は連合で中間投稿が欠けた場合のために残す
  - 起点カードに、リモート投稿なら元サーバーへの外部リンク "View on <host>" を統計行の下に添える (プロフィールヘッダの同名リンクと同型、ADR-0011 の「外部と明示した副次的導線」)。サブメニューは作らない — 1 項目しか入らない。**Phase 2 でカードに操作メニューができたら、このリンクはそこへ移す**。タイムラインのカードには置かない — 行のタップは会話を開くもので、外への出口は読みに着いた場所に置く
- [x] 絵文字リアクション・ブースト・ファボの「誰が」一覧をスレッド (投稿詳細) から開ける (`/api/v1/pleroma/statuses/:id/reactions`、`/reblogged_by`、`/favourited_by`。3 本ともページネーション無し — PLAN の落とし穴参照)。
  - 1 ページ + タブ 3 本 `/statuses/:id/favourited_by` / `/reblogged_by` / `/reactions`。タブはパスのセグメント (`?type=` ではない — `<A>` の `aria-current` はパス一致でしか付かず、タイムラインとプロフィールのタブバーと同じ慣習)。タブ切替は `replace` (同じページ内の移動なので履歴を増やさず、Back 1 回でスレッドへ。プロフィールのタブは push のまま)。見出し・タブの count・一覧はページ内で独立に届く — レイアウトの境界で待つと直接到着で面ごと隠れる
  - 入口は**スレッドの起点カードのみ**: チップと ActionBar の間に「N boosts · N favourites · N reactions」の統計行を置き、各項目が該当タブへのリンク。ファボ / ブーストのアイコン横の数字をリンクにする案は撤回 — アイコンのアフォーダンスは「実行する」であって「誰がしたか見る」ではなく、Phase 2 でアイコンが本当に操作になると同居できない。起点カードの ActionBar は数字を消してアイコンだけにする (同じ数字を 2 度出さない)。0 件の項目は行から消し、全部 0 なら行ごと出さない — 一覧が伏せられて count と行数が食い違う場面を減らす。チップはリンクを持たない (Phase 2 でタップ = リアクション)。タイムライン・祖先・子孫のカードはアイコン + 数字のまま、リンク無し — Phase 2 で数字が操作 (ファボ / ブースト) になる見通し。Mastodon web (投稿詳細の meta 行) / Bluesky (スレッド起点の "N reposts · N likes") / akkoma-fe (focused のみの users 行) と同型
  - reactions は 1 ページに絵文字ごとのグループ見出し (カードと同じチップ) + アカウント行で、per-emoji ルートは持たない。見出し帯は行より低く `bg.subtle`、下罫線、チップの横に `N people` (N はグループの `count` — Akkoma は見えないアカウントを落とす前に数えるので行数と食い違いうる)、`position: sticky` でスクロール中も今どの絵文字の下にいるかが残る。絵文字タブで絞る Misskey 型は状態と URL が増えるので採らない (絵文字の種類が多くて帯が縦に増えすぎたら次段)
  - 404 / 403 は Retry 付きのエラー行、`[]` (非公開・`show_reactions: false` 込み) は空文言で、区別しない。空文言は "No favourites to show." のようにゼロを断定しない — タブには投稿の count がそのまま出るので、Akkoma が一覧を伏せるか知らないアカウント・ブロック済みを落とすと count と行数が食い違う
- [x] プロフィールを投稿 / 返信 / メディアのタブ付きで閲覧できる。フォロー関係 (フォロー中 / されている) が見える。フォロー一覧 (フォロー中 / フォロワーの一覧) もこのストーリーに含む。フォロー操作は Phase 2。ワイヤーは [docs/design/profile-page-20260830.html](./design/profile-page-20260830.html)
  - 投稿リストは `exclude_replies=true`。Akkoma はこのフラグでセルフリプライも落とすが、クライアント側フィルタはページネーションを壊すため癖ごと受容
  - 投稿詳細を開いて戻ったときにプロフィールの読み位置と蓄積したページを失わない (ADR-0004 amendment: 保持は path キーの履歴 stack、復元は pop のときだけ)。タイムライン → スレッド → 戻るの挙動と揃える
  - フォロー一覧: `/accounts/:acct/following` / `/followers` を葉ルート 2 本として追加、タブバーは投稿 3 タブのまま (5 タブは 375px で折れる)。入口はヘッダの count で、2 軸を独立に扱う — `hide_*_count` なら数字の代わりに "hidden"、`hide_*` (一覧そのもの) が立っていればリンクを付けない。非公開一覧は Akkoma が本人以外に 200 + `[]` を返すので「フラグ + 空応答」で文言を出し、本人判定はしない。既知の割り切り: 本人にも "hidden" と出る上、`hide_*` を立てた本人は自分の一覧への入口リンクも失う (URL 直打ちなら Akkoma は本人に実一覧を返す)。本人判定 (verify_credentials の id) は Phase 2 のフォロー操作と同じスロット。行はアバター + 表示名 + acct の 1 anchor、bio / 関係バッジは持たない。一覧の `:id` は flake id のみで nickname は 404 (PLAN の落とし穴)
  - pinned 表示: Posts タブの先頭に `?pinned=true` で取った投稿を "Pinned" マーカー付きで並べる。akkoma-fe / Mastodon web / Phanpy / Elk に揃え、Posts タブのみ、時系列リストとの dedupe はしない (同じ投稿が 2 回出てよく、マーカーは帯側だけ)、取得にタブの filter は付けない (Akkoma は `pinned` と `exclude_replies` を AND で結ぶ — PLAN の落とし穴)。リモートアカウントは複数件入るので帯は複数行になりうる。既知の限界: 帯は読み位置の保持対象外なので、長くスレッドに滞在してから Back で戻ると帯が復元後に挿入され、読み位置がその高さ分ずれうる。dogfooding で気になったら保持に載せる
  - ヘッダ: 表示名はバナーの下端から始め、アバターだけがバナーに掛かる。Following・Follows you のバッジは枠なしの `bg.subtle` の pill (枠付きはリンクの隣で押せそうに見える)。"N posts" / "N following" / "N followers" の count はそれぞれ該当タブ・一覧へのリンク。following・followers 一覧の上では投稿 3 タブを出さない (一覧が自分の見出しを持つ)。ヘッダの count リンクと 3 タブはスクロール位置を先頭に戻さない — ヘッダが残ったまま下だけ差し替わるページ内のセクション切替であって到着ではない (誰が一覧のタブを `replace` にしたのと同じ理屈)。差し替え中の読み込み行は viewport の高さを確保する — 一瞬 1 行に縮むと文書が viewport より短くなり、ブラウザが scrollY を 0 に丸める
  - プロフィールの URL prefix は `/accounts/:acct`。`/users/:nickname` は Akkoma が actor 用に root で所有しており、リロード・直リンク・タブ復元で SPA ではなく Akkoma の応答が返る (PLAN の落とし穴参照)。名前はクライアント API の `Account` に合わせた (`/actors/` は AP の語でアプリに対応物が無い)
  - ヘッダのワードマーク "utaita" をインスタンス名にするかは保留。`/api/v1/instance` の query がまだ無く、Phase 2 で投稿の文字数上限・添付上限を取りに行くときに同じ query で名前も取れるので、そこで判断
- [x] プロフィール動線: StatusCard のアバターと名前ブロックを `/accounts/:acct` へのリンクにする (カード全体タップの会話オープンに吸われないこと — メンションと同じ扱い) / ヘッダのワードマークをホームタイムラインへのリンクにする (プロフィールに Back ボタンは置かない — スレッドの Back は history back でしかスクロール復元が効かない事情から来たもので、ワードマーク = ホーム先頭で足りる) / リモートアカウントのヘッダに元サーバーのプロフィール (`account.url`) への外部リンク "View on <host>" を添える (ローカルには受信した投稿しか無いため。新しいタブで開く — ADR-0011) / 読み込み中に縦スクロールバーが消えてカラムが右にずれるのを `scrollbar-gutter: stable` で止める
- [x] タイムラインとスレッドの status 表示は full-bleed + 罫線。per-status のカード枠・角丸・gap は縦密度と本文幅を削るため廃止し、行 (左右 inset 12px + border-bottom 1px) にする。デスクトップはカラム単位で panel を着せ、QuoteCard は引用の異質さを示す信号としてカードのまま。スレッドは背骨ルールを画面端に置き本文 inset を左右対称にする — subject の 2 チャンネルマークは維持。判断理由と棄却案は [docs/design/timeline-density.md](./design/timeline-density.md)
- [x] スレッド画面の小修正: Back ボタンのアイコン化と "Conversation" 見出しの整理 (canGoBack の出し分けは維持) / スレッド内の投稿時刻を時刻精度で表示 (タイムラインカードは日付のまま。ロケール "en" のハードコードには触れない — Phase 4) / UnfetchedParent をプレースホルダーカード化 / カスタム絵文字の拡大 (本文 1.25em ≈ 20px は akkoma-fe 実測 38px の約半分だった) / "Not connected to this post" セクションの見出し + 説明文を面の先頭のヘッダー帯に収める (密度改修で前後が面になり、canvas 上の裸のテキストの浮きが目立つ) / 絵文字リアクションのチップも本文と同寸に拡大 (akkoma-fe も本文とリアクションを同寸で描く。件数の数字はメタ情報として xs 据え置き)

## Phase 2 — 書き込み

- [ ] 通知を読め、どこまで読んだかが分かる。メンション・ブースト・フォロー・絵文字リアクションが一目で区別でき、`pleroma:emoji_reaction` や `move` など未知の type で落ちない。未読が見分けられ、閲覧で既読になる。
  - Phase 1 から移動。既読を付ける経路 (`POST /api/v1/pleroma/notifications/read` は `write:notifications`、`POST /api/v1/markers` は `follow` / `write:blocks`) がすべて write scope で、Phase 1 の `read` トークンでは `pleroma.is_seen` が全件 false に張り付いて未読表示が成立しない。一覧だけ先に Phase 1 で出す案は、既読前提で行と store を 2 回設計することになるため棄却。着手はトークン scope の変更 (`read` → `read write`、ログイン画面の story 参照) の直後
- [ ] CW・公開範囲 (`local` 含む) 付きで投稿でき、カスタム絵文字の補完が効く。
- [ ] alt text 付きで画像を添付でき、アップロードの進捗が見える。
- [ ] タイムライン上からファボ・ブースト・ブックマーク・絵文字リアクションができる。
- [ ] プロフィールからフォロー / 解除でき、承認制アカウントには申請中の状態が表示される。
- [ ] アカウント・ハッシュタグ・投稿を検索できる。
- [ ] お気に入り / ブックマークした投稿の一覧を閲覧できる (`/api/v1/favourites`, `/api/v1/bookmarks`)。
- [ ] ログイン画面をワイヤー ([docs/design/login-20260712.html](./design/login-20260712.html)) に合わせて仕上げる (Phase 1 では意図的に直さなかった — 接触頻度が低く、Phase 2 のトークン scope 変更 (`read` → `read write`) で全員が再認可のためログインを通り直すタイミングに実装するのが同スロットで安い)

## Icebox

- 見逃した投稿のキャッチアップダイジェスト (Phanpy 風)
