Decisions

  • Zone order: header image → avatar + names (avatar overlaps the header image bottom edge) → note → fields → counts → tab bar → post list.
  • Tab-first design (2026-08-30): three tabs — Posts / Posts & replies / Media, X-style. The bar and the latter two tabs ship in session #2; session #1 renders the Posts list as the future default tab's content, so nothing is thrown away.
  • This session renders the "posts" list only (exclude_replies=true). Akkoma also drops self-replies with this flag — accepted as-is; client-side filtering would break pagination.
  • Counts are display-only. No follow button (Phase 2), no relationship badge (#2), no tabs (#2), no pinned (last).
  • Post rows reuse StatusCard chrome-free with page-local row chrome, same as the timeline — per-framing chrome is the StatusCard contract, not duplication.
  • Flat append-only store with a single max_id cursor; no segments/gap/refresh (those exist for streaming and refresh, which the profile list doesn't have).
  • Navigating /users/alice → /users/bob recreates the whole body (keyed Show on the loaded account) — no manual reset of the post store.

Field sources (verified against the reference instance, 2026-08-30)

  • GET /api/v1/accounts/{acct} → header / avatar / display_name + emojis / acct / note (HTML) / fields[].name,value / statuses_count, following_count, followers_count.
  • GET /api/v1/accounts/{id}/statuses?exclude_replies=true&limit=40 → post list; max_id pagination.
  • 2026-08-30 live checks: remote acct user@domain resolves as the path param — both raw @ and %40-encoded return 200 with the same account, so openapi-fetch's path encoding is a non-issue. exclude_replies=true drops self-replies too (a self-reply present without the flag disappears with it) — confirmed. with_relationships=true embeds pleroma.relationship (full shape, even anonymously — all-false then); recorded for session #2, unused here.
